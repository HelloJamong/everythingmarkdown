# EverythingMarkdown 검증 명세

- 작성일: 2026-09-08
- 대상: [구현 설계](design.md)
- 상태: 전체 MVP의 미래 검증 계약. P0 테스트 결과는 [P0 검증 기록](p0-validation.md)을 따르며 A01~A26 전체 통과를 의미하지 않는다.
- 테스트 도구: 초기에는 Python `unittest`/`unittest.mock` 사용 가능. lint/typecheck 도구와 새 개발 의존성은 구현 환경 확정 때 선택하며 이번에는 설치하지 않는다.

## 현재 실행 범위 변경 (2026-09-08)

사용자 요청으로 Windows/macOS 실환경 테스트는 배포 후 별도 단계에서 수행한다.
A20과 A02/A03/A05/A07/A17~A19 등에서 실제 OS·창·콘솔에 의존하는 부분은 이관·미실행으로 기록한다.
해당 기준의 로컬 단위·통합 테스트 가능 부분은 유지한다. 수용 기준 자체를 삭제하거나 통과로 바꾸지 않는다.
실환경 테스트는 현재 P1~P4 착수/개발 완료의 선행 조건이 아니며, 목표 OS별 배포 파일 빌드는 여전히 필요하다.

## 2. 계층별 검증

### 단위

- `service.py`: 상대/절대 경로, 크기 경계(100 MiB 이하/초과), 출력 이름, 심볼릭 링크, 기존 경로 충돌, 예외 변환, 배타적 생성과 실패 정리.
- `markitdown_adapter.py`: v0.1.7 API의 `result.markdown` 추출, 명시 컨버터 1개 등록과 자동 builtins/plugins 비활성, 위장 ZIP 거부/OOXML 구조 검증, 알려진 외부 예외와 예상 밖 예외의 안전한 매핑, 빈 결과 판정.
- `cli.py`: argparse, stdout/stderr 분리, TTY 여부, 인자 없는 파이프 실행, 종료 코드.
- `gui.py`: fake service/queue를 이용한 상태 전이와 닫기 예약. Tk 실제 이벤트 루프 검증은 디스플레이가 있는 환경에서 별도 수행.
- OS 권한/ENOSPC는 결정적으로 실패 주입하고, 가능한 실제 환경에서 추가 재현한다. 관리자 실행 때문에 권한 테스트가 무효가 되지 않게 한다.

### 실제 엔진 통합

- 자체 생성한 개인정보 없는 TXT, CSV, HTML, 텍스트 PDF, DOCX, PPTX, XLSX 각 1개 이상을 버전 관리한다. fixture 생성 도구는 앱 런타임 의존성으로 넣지 않는다.
- 문서 종류별 핵심 문자열/헤더/셀 보존을 확인하고 라이브러리 버전 간 전체 Markdown 공백 변화에만 실패하는 과도한 스냅샷은 피한다.
- 동일 fixture의 GUI/CLI 출력은 같은 엔진 버전에서는 정확히 비교한다.
- 네트워크 시도를 탐지하는 테스트 가드와 OS 수준 네트워크 차단 실행을 병행한다. 연결 실패를 숨기고 결과만 만든 경우도 통과시키지 않는다.
- 손상 문서/외부 참조 HTML/스캔 PDF/같은 stem 문서 fixture를 포함한다. 라이브러리가 지원하는 더 많은 포맷이 제품 지원표에 자동 편입되지 않도록 allowlist를 검사한다.

### 플랫폼·패키징 E2E

| 환경 | 실행 방식 | 필수 확인 |
|---|---|---|
| Windows 11 x64 | PowerShell/CMD CLI, GUI 실행 파일, 시작 위치 지정 바로가기 | 입력 프롬프트·stdout/stderr·exit code, GUI 불필요 콘솔 없음, 한글/공백 경로, CWD |
| macOS 14+ Apple Silicon | 터미널 CLI, GUI 바이너리 직접 실행, Finder `.app` | Tcl/Tk 포함, CWD 차이 노출, 쓰기 불가 시 명확한 오류, 한글 경로 |

- 각 OS에서 frozen 형태로 7개 포맷을 재검증한다. 개발 venv에서의 성공으로 대체하지 않는다.
- GUI는 정상 선택·진행·성공·실패 화면, 키보드 탐색, OS 확대 배율에서 컨트롤 잘림 여부를 기록한다.
- Finder/바로가기 경로가 쓰기 불가일 때 실패 안내가 정상인 것과 기본 더블클릭 변환 성공은 다른 기준이다. 쓰기 가능한 시작 위치를 준 실행에서 실제 변환 성공이 필수다.
- 지원 OS/CPU 범위를 넓히면 해당 조합을 행렬에 추가하고 검증 전에는 지원 완료라고 표현하지 않는다.

## 3. 구현 후 실행할 검증 명령과 증거

초기 제안 명령이며 현재 실행할 코드/테스트는 없다.

```sh
python -m unittest discover -s tests/unit -v
python -m unittest discover -s tests/integration -v
python -m compileall -q src tests
```

- src-layout 패키지 설치/환경 준비 및 fixture 준비를 먼저 완료한다. 네트워크 차단 테스트는 설치 이후 별도 실행한다.
- lint/typecheck는 채택 도구·설정이 생기면 정확한 명령을 README에 고정하고 CI에서 실행한다. `compileall`을 lint/typecheck 성공으로 보고하지 않는다.
- 증거: 실행 명령, OS/CPU/Python/MarkItDown/패키저 버전, 종료 코드, 테스트 개수, frozen smoke 로그, UI 캡처, 알려진 미검증 항목.
- 현재 설계 단계에서는 문서 간 일관성·요구사항 매핑·순차 Architect/ Critic 검토만 검증한다. 앱 동작·배포 가능성은 아직 검증하지 않았다.
